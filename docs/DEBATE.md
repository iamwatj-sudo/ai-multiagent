## Brand Strategist

**รอบ 1 — เปิด**
- Positioning แคบ ("นักพัฒนา .NET ที่ต้องดูแลระบบ Web Forms / VB…หยุดเพื่อรื้อเขียนใหม่ไม่ได้") คือจุดแข็ง — ค้านการขยายเป็น "AI developer"
- Headline เดิมยัดสามเรื่อง (เทค + วิธี + จุดยืน AI) · tagline "ย้ายของเก่า โดยไม่ต้องรื้อทั้งหมด" แข็งกว่าแต่ซ่อนใน `## Tone` ซึ่ง parser ไม่อ่าน
- ความน่าเชื่อถือบาง: มีแค่ "ผมกำลังทำงานแบบนี้อยู่" · audience รอง (tech lead ผู้ตัดสินใจย้าย) ยังไม่ระบุ

**รอบ 2** — ค้าน Frontend ที่จะเลื่อน Playbook: ไม่มี Playbook = เว็บแนะนำตัวเปล่า ๆ · Playbook เป็น `.astro` static หน้าเดียวได้ · เห็นด้วย Devil ครึ่งเดียว: "รวบรวมบทเรียน…" → "กำลังจด" แต่ "คนตรวจทุกขั้น" เป็นจุดยืน ไม่ใช่สถิติ — พิสูจน์ด้วย checklist ใน Playbook · รับ Reviewer ให้ใช้ "AI เป็นผู้ช่วย" คำเดียว

**รอบ 3** — ค้าน UX ที่ย้ายบรรทัด AI ไป About อย่างเดียว (About คนไม่คลิก) → เสนอบรรทัดเล็กที่สามแยกจาก subline · Bio: จำนวนปีต้องเป็นตัวเลขจริงจากวัฒน์ ไม่มีให้ตัด · เสนอธีมสว่าง off-white อุ่น + dark ตามระบบ

**รอบ 4** — ยืนบรรทัด AI บน Hero · ยอมไม่มีช่องประเภท แต่ค้านการเติมคำนำหน้า (ข้อมูลปน) → ใช้ placeholder · ยืนข้าง Devil เรื่องปิดปุ่มตอน 501 และห้ามใช้ "เร็ว ๆ นี้"

**รอบ 5 — ปิด:** รับทั้ง 4 ข้อ · ขอให้บรรทัด AI มาจาก PROFILE ไม่ hardcode

**สิ่งที่ต้องจำ (session ถัดไป)**
- Positioning แคบ · tagline = H1 · ห้ามขยายเป็น "AI developer"
- "AI เป็นผู้ช่วย" คำเดียวทั้งเว็บ · "คนตรวจทุกขั้น" ต้องมี checklist รองรับเสมอ
- ห้ามเคลมเกิน: "กำลังจด" · "ฉบับกำลังเขียน" · ปีจริงเท่านั้น · ห้ามสัญญาเวลา

## UX Critic

**รอบ 1 — เปิด**
- Home ไม่มีเส้นทาง: `index.astro` เอา Bio ก้อนใหญ่ + `Audience:` ขึ้นบนสุด · ไม่มีปุ่มไป Playbook (Must ข้อแรก)
- บนมือถือ Bio 4 ย่อหน้าใน `<p>` เดียว · เมนูไม่ตรงงาน (Interests ไม่อยู่ใน Must · Guestbook เป็น Nice)
- ฟอร์ม Contact โชว์ `POST /api/contact` · ป้ายอังกฤษ · ไม่บอกว่าส่งแล้วเกิดอะไร · Guestbook ใช้ `innerHTML` แทรก `${e.name}` (XSS)
- ท้าทายธีมมืดทั้งเว็บกับ "อ่านนานไม่ล้า"

**รอบ 2** — ยอม Devil: ถอน "เคสศึกษา" ออกจากเมนู (NDA) · ค้าน Frontend: Playbook หน้าเดียวไม่ใช่ CMS · ครึ่งเดียวกับ Brand: tagline เป็น H1 ได้ แต่บรรทัดรองต้องบอก "Web Forms → ASP.NET Core MVC"

**รอบ 3** — ยังค้าน Brand: subline สองเรื่องยาว 3–4 บรรทัดบนมือถือ · ออกแบบฟอร์ม: ชื่อ · อีเมล (hint "ใช้ตอบกลับเท่านั้น ไม่แสดงบนเว็บ") · ข้อความ · ยืนยัน "ได้รับข้อความแล้ว ผมจะตอบกลับทางอีเมลที่คุณให้ไว้" ไม่สัญญาเวลา · ธีมสว่าง + contrast ≥4.5:1 · เห็นด้วยลบ `interests.astro` พร้อมลิงก์

**รอบ 4** — ยอม Brand ถ้าบรรทัด AI ≤1 บรรทัดบนมือถือและแยกจาก subline · ไม่มีช่องประเภท ใช้ placeholder · **เปลี่ยนมาทาง Devil**: ตอน 501 แจ้งเหนือฟอร์ม + ปิดปุ่ม + ซ่อน "ถามผม" (เว็บไม่มีช่องทางติดต่ออื่น)

**รอบ 5 — ปิด:** รับทั้ง 4 ข้อ · flag เปิดฟอร์มเก็บไว้ที่เดียว ให้งาน Lab 05 เป็นคนพลิก

**สิ่งที่ต้องจำ (session ถัดไป)**
- จอแรกมือถือ: H1 tagline · subline เทค · บรรทัด AI ≤1 บรรทัด · ปุ่ม "อ่าน Playbook" · ทุกลิงก์ชี้หน้าที่มีจริง
- Contact: ป้ายไทย ไม่โชว์ endpoint/error ดิบ · 501 = ปิดปุ่ม + แถบแจ้ง · ห้ามอ้าง "90 วัน" จนมีการลบจริง
- a11y 6 ข้อเป็น Must · สถานะรายขั้นเป็นข้อความ ไม่ใช่สีอย่างเดียว

## Devil's Advocate

**รอบ 1 — เปิด**
- "คนตรวจทุกขั้น" / "รวบรวมบทเรียน…จากงานจริง" ยังไม่มีหลักฐาน — วันเปิดไม่มีบทความ = เคลมเกิน
- Must เยอะเกิน (Playbook, เคส, Before/After, workflow) ทั้งที่ไม่มีระบบบทความ
- เคสศึกษา "ตัวเลขเป็นช่วง" + ขนาดระบบ + อุตสาหกรรม → ระบุตัวลูกค้าได้ · "คลัง prompt" ขัดกฎ "ห้ามยก prompt/output ดิบ"
- Guestbook = spam + คำรับรองปลอม · `github: Wat` อาจเป็นของคนอื่น · `demo@example.com` ขัด "ใช้ฟอร์มแทนโชว์อีเมล"

**รอบ 2** — ปีประสบการณ์รับได้ แต่เคสใน Bio ต้องเป็นสถานการณ์ทั่วไปไม่มีตัวเลข/อุตสาหกรรม · ไม่ได้ขอระบบบทความ ขอ Playbook static 1 หน้า · แก้ parser = blocker ก่อนทุกอย่าง · เมนู/CTA ที่ชี้หน้าที่ยังไม่มีแย่กว่าไม่มี

**รอบ 3 — ท้าทายฉันทามติ**
- Bio บอก "กำลังทำงานแบบนี้อยู่" = ยังเดินไม่ครบ 5 ขั้น → Playbook ต้องเป็น "ฉบับกำลังเขียน" + สถานะรายขั้น
- `insertContact` ยัง 501 (OpenCode) — UI ขึ้นก่อน ผู้ใช้กดส่งแล้วเจอ error
- **PDPA** (ยังไม่มีใครพูด): ไม่มีระยะเก็บ สิทธิ์เข้าถึง วิธีลบ · ตัวเลือกประเภท = เพิ่ม schema

**รอบ 4** — ยอม Brand ถ้าบรรทัด AI ลิงก์ไป checklist · ยอมวิธีเติมคำนำหน้าของ UX (payload เดิม) · ยอมครึ่ง: กรอกได้ แต่แถบแจ้งต้องอยู่เหนือฟอร์มก่อนพิมพ์ · ยืน PDPA + เพิ่มวิธีขอลบข้อมูล

**รอบ 5 — ปิด:** รับข้อ 1, 3, 4 · **dissent ข้อ 2**: placeholder อย่างเดียวแยกข้อความเสนอหัวข้อไม่ได้ → เสนอ placeholder บอกให้ขึ้นต้นด้วย "หัวข้อ:"

**สิ่งที่ต้องจำ (session ถัดไป)**
- ห้ามเคส/ตัวเลข/อุตสาหกรรม/prompt-output ดิบจากงานจริงบนเว็บ จนมี checklist NDA
- ฟอร์มเปิดเมื่อ lab05-api เขียวเท่านั้น · PDPA (ระยะเก็บ/วิธีลบ) ยังเป็น loop ค้าง
- ห้ามโชว์อีเมล/ลิงก์ GitHub จนวัฒน์ยืนยัน · จำนวนปีต้องเป็นตัวเลขจริง

## Reviewer (`@reviewer`)

**รอบ 1** — Must: `public-site.test.ts` ไม่สแกนเนื้อหา PROFILE ที่ render ผ่าน `loadProfile()` · regex จับแค่ lab+เลข/แล็บ — "คอร์ส"/"course" หลุด · placeholder อีเมล/GitHub = ลิงก์เสีย · Should: validate ฝั่ง server · Tone/Brainstorm ต้องไม่ render
**รอบ 2** — ยืนยันจากโค้ด: `profile.ts` บรรทัด 42 `(?=^##\s|$)` + flag `m` → ต้องเทสต์ RED ก่อนแก้ · `innerHTML` = XSS · `profile.ts` ไม่อยู่ในตาราง ownership → เสนอ Frontend · รับ `## Tagline` ถ้ามี FALLBACK + ย้ายออกจาก Tone + guard ครอบคลุม
**รอบ 3** — ลบ `interests.astro` ต้องลบลิงก์ใน `BaseLayout.astro` และ `index.astro` ด้วย · `api/interests.ts` เรียก `loadProfile()` → แก้ parser เปลี่ยนผล API → handoff OpenCode · เทสต์ HTML ที่ render จริง + เมนูตอบ 200 · a11y 6 ข้อ
**รอบ 4** — ค้านบรรทัด AI แบบ hardcode (เพี้ยนจาก PROFILE) · ค้านเติมคำนำหน้า (สัญญา API แอบ ๆ) · ยอมปิดปุ่มตอน 501 แต่เก็บโค้ดจัดการ 501 ไว้ · "90 วัน" ต่อเมื่อมีกลไกลบ · Must เพิ่ม: `<meta description>` ใน BaseLayout มี "course"
**รอบ 5 — ปิด:** **dissent ข้อ 1** ถ้า hardcode → ทางลด: ให้ข้อความมาจาก PROFILE ผ่าน parser
